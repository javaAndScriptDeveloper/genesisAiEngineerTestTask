# 02 · `verify` — перевірка стійкості висновку

## Що робить
`verify --run runs/<slug>` бере готовий запуск `analyze` і для кожного рядка (тема × мова) виконує
п'ять незалежних перевірок, які **не покладаються на ті самі дані й ті самі припущення**, що дали
основний висновок. Результат — вердикт `robust | mixed | fragile` з причинами, у `verify.md` (≤ 30
рядків, друкується в stdout) та `verify.json`.

| Перевірка | Що порівнюємо | Коли тривога |
|---|---|---|
| Пристрої | тренд desktop vs mobile-web (окремі запити до API) | знаки різні або розрив > 15 п.п. |
| Боти | `all-agents` vs `user`: частка не-людського трафіку у вікні | > 50 % (попередження від 35 %; звичайна стаття має 20–30 % павуків) |
| Чутливість до вікна | тренд без останніх 3 міс. і без перших 3 міс. (з кешованого ряду) | знак змінюється (крім «плоских» трендів у межах ±5 п.п.) |
| Контрольна перевірка даних | один випадковий закритий місяць перезапитуємо напряму (повз кеш) | значення не збігається |
| Базова лінія розділу | сирий тренд статті vs тренд усього розділу | показує, скільки «росту» пояснює сам розділ |

Вердикт: `fragile`, якщо будь-яка перевірка дала тривогу (alert); `mixed`, якщо лише попередження
(розрив між пристроями 10–15 п.п., боти 35–50 %, розкид трендів > 25 п.п.); інакше `robust`.

Реальний приклад (`examples/03-english-multi/verify.md`): рядок «Englische Sprache» (de), який `analyze`
позначив як low confidence, у `verify` отримав **74.8 % не-людського трафіку** — саме тому його «стабільний»
тренд не варто брати за основу для рішення. Рядок «Астрономія» (uk): −41 %/рік на десктопі і −52 %/рік на
мобільних, боти 27 % — падіння підтверджується на всіх зрізах (`mixed` лише через розрив між пристроями).

## Навіщо
Завдання просить, щоб навичка допомагала агенту **перевіряти висновки**. `confidence` в `analyze`
оцінює якість одного ряду (піки, покриття, монотонність). `verify` відповідає на інше питання: чи
отримаємо той самий висновок, якщо змінити спосіб вимірювання? Якщо ріст видно лише на мобільних, лише з
ботами або лише завдяки останнім трьом місяцям — це не сигнал для інвестицій.

## Як користуватись
```bash
uv run scripts/wiki_interest.py analyze --topic "астрономія" --langs uk --months 24 --out runs/astro-uk
uv run scripts/wiki_interest.py verify --run runs/astro-uk
```
Агент викликає `verify`, коли користувач питає «наскільки цьому можна довіряти?», «а це не боти?»,
«а якщо взяти інший період?» — або сам, перш ніж рекомендувати інвестувати. Додаткові запити до API:
3 на рядок (desktop, mobile-web, all-agents) + 1 контрольний; усе кешується.

## Як перевірено
- Юніт-тести з замоканим HTTP: розбіжність пристроїв → `fragile`; частка ботів ≈57 % → `fragile`;
  усе узгоджено → `robust`; контрольна перевірка ловить підмінене значення в кеші.
- Живий прогін на прикладах з `examples/` (див. `verify.md` у кожній папці).
- Прогін на Haiku 4.5 через `eval/` з промптом «наскільки цьому росту можна довіряти?» — модель викликає
  `verify` і цитує вердикт із причинами.
