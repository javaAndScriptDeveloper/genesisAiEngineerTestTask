# 04 · `discover` — теми, що ростуть, яких користувач не називав

## Що робить
`discover --lang <код>` бере топ-1000 статей мовного розділу за останній закритий місяць і той самий
місяць рік тому, переводить перегляди у «на мільйон переглядів розділу», викидає службові сторінки
(головна, `Спеціальна:`, `Категорія:` — префікси беруться з `siteinfo` кожної вікі, тому працює для будь-якої
мови) і технічний шум (`wiki.phtml`), і повертає статті з найбільшим ростом частки уваги. Статті, яких рік
тому не було в топі, отримують точне значення року тому окремим запитом (`new in top? = yes`).

Флаги: `--include` / `--exclude` (регулярні вирази по назві, напр. `--include "астроном|косм"`,
`--exclude "фільм|серіал"`), `--month YYYY-MM`, `--limit`, `--min-views`.

**`--sustained`** — головне: для кожного кандидата навичка тягне 24-місячний ряд (кешується) і додає
очищений від піків ріст за рік та `confidence`. Так «Ти — космос» (фільм, +632 % за місяць) і справді
стійка тема відрізняються з першого погляду: перша має пік і низьку довіру, друга — рівний ріст.

## Навіщо
Три приклади із завдання — про теми, які засновник уже назвав. Але ключове питання «які теми розвивати
далі?» передбачає й **пошук** тем. `discover` дає список кандидатів з даних, а не з голови, і одразу
чесно попереджає: топ-листи — це увага (новини, серіали, люди), а не попит; далі — `analyze --titles`
для повного аналізу. Це перший крок roadmap-пункту «режим відкриття тем» — реалізований.

## Як користуватись
```bash
uv run scripts/wiki_interest.py discover --lang uk --limit 20                       # що росте взагалі
uv run scripts/wiki_interest.py discover --lang uk --include "астроном|косм|планет" --exclude "фільм" --sustained
uv run scripts/wiki_interest.py discover --lang pl --month 2026-06 --include "język|gramat" --sustained --out runs/disc-pl
```
Результат — `discover.md` (≤ 40 рядків, друкується) і `discover.json`; останній рядок пропонує готову
команду `analyze --titles …` для першого кандидата. Приклад реального виводу: `examples/04-discover-pl/`.

## Обмеження
Топ-1000 не бачить малих статей (нішеві теми до топу не потрапляють — для них є `analyze` за назвою);
top-ендпоінт не ділить трафік за `agent`, тому `--sustained` (який рахує `agent=user`) — обов'язковий
фільтр перед висновками. Порівняння «місяць до місяця рік тому» чутливе до сезону — тому воно й
доповнюється 24-місячним трендом.

## Як перевірено
- `test_discover_ranks_rising_articles_and_filters_namespaces` — сортування за ростом частки, виключення
  головної/службових сторінок, точний рік-тому для нових у топі, пропозиція `--titles`.
- `test_discover_filter_and_exclude_regex`, `test_discover_rejects_current_or_future_month`, `test_discover_bad_month_exit_3`.
- `test_discover_sustained_adds_trend_and_confidence_and_drops_junk` — 24-місячний тренд і довіра на кандидатах,
  плоский ряд → ріст ≈ 0 (увага, не тренд), `wiki.phtml` відкинуто.
- Живі прогони для `uk` і `pl` (вересень 2026): у топі uk — актуальні персони й фільми; з фільтром і
  `--sustained` кандидати одразу розшаровуються за довірою.
